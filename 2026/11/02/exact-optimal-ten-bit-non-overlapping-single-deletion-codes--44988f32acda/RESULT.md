# Exact optimal ten-bit non-overlapping single-deletion codes

## Finding
For every integer \(2\le n\le10\), define \(J(n)\) as the maximum cardinality of a binary length-\(n\) code that is simultaneously non-overlapping (cross-bifix-free) and capable of uniquely correcting any one deletion within a codeword. Then

\[
\bigl(J(2),J(3),\ldots,J(10)\bigr)=(1,1,1,1,2,2,4,6,9).
\]

At length \(10\), **exactly twelve** coordinate-labeled codebooks attain cardinality \(9\). Under the group generated by reversal of every word and global bit complementation, these twelve codebooks form exactly three orbits, each of size four. This is an exhaustive classification; the twelve codebooks are printed in `optima.tsv`.

An optimal length-ten codebook is:

```text
0000000011
0000101011
0001001111
0010000111
0010110011
0010111111
0100100011
0100111011
0101010111
```

## Assumptions and scope
All strings are fixed-length indexed binary words; positions have a specified left-to-right order, with no cyclic wraparound. A length-\(n\) code \(C\subseteq\{0,1\}^n\) is **non-overlapping** when, for every \(u,v\in C\) (including \(u=v\)) and every \(1\le j<n\), the first \(j\) symbols of \(u\) differ from the last \(j\) symbols of \(v\). Let \(D(u)\subseteq\{0,1\}^{n-1}\) be the set of distinct strings obtained by deleting one symbol from \(u\). The code corrects one deletion exactly when \(D(u)\cap D(v)=\varnothing\) for all distinct \(u,v\in C\). Repeated deletion positions producing the same output are counted only once.

A labeled codebook means an actual subset of \(\{0,1\}^n\), without identifying it under any permutation. Reversal and bit complement preserve both constraints; arbitrary coordinate permutations generally do not. The theorem includes every codebook, not merely linear codes or one family of constructions.

## Proof
**Binary orientation reduction.** The length-one prefix/suffix prohibition applied to a word itself forces its first and last bits to differ. Applied to every pair of codewords, it forces *all* first bits to be equal, and therefore all last bits to be the opposite bit. Consequently every nonempty feasible code is entirely in the orientation class \(0\cdots1\) or entirely in \(1\cdots0\). Complementation interchanges these classes. It suffices to enumerate the first class, then double counts of nonempty optimal codebooks.

**Exact compatibility graph.** For each \(n\) let \(V_n\) contain all length-\(n\) unbordered binary words beginning in zero and ending in one. For distinct \(u,v\in V_n\), join \(u,v\) by an edge precisely when neither direction of prefix/suffix overlap occurs for any proper nonempty length, and when \(D(u)\cap D(v)=\varnothing\). Every feasible oriented code is a clique, and every clique is a feasible oriented code, by the definitions. Thus \(J(n)\) is the clique number of this finite, explicitly specified graph.

**Exhaustive finite certificate.** `verify.py` regenerates every element of each \(V_n\), both compatibility tests, and every clique by increasing vertex indices. It recursively intersects the available later-indexed vertices with the later-neighbor set of the last selected vertex. By induction, each clique has one increasing listing and occurs in precisely one branch; no nonclique can enter a branch. This is an exhaustive proof of the claimed finite counts, not a sample or extrapolation. `census.tsv` contains the counts of *all* oriented cliques by size for every \(2\le n\le10\).

The oriented vertex counts are \(1,2,3,6,10,20,37,74,142\). The maximum clique sizes are respectively \(1,1,1,1,2,2,4,6,9\). At \(n=10\), the complete oriented clique-count vector, indexed by clique cardinality \(0,1,\ldots,9\), is

\[
(1,142,4566,51196,216875,347859,200412,37440,1800,6).
\]

In particular, there are six oriented size-nine cliques and none larger. Complementing each yields six additional distinct codebooks, proving both the upper bound and the total count of twelve. Directly applying reversal, complementation, and their product to the complete list in `optima.tsv` produces precisely three disjoint four-element orbits. The displayed nine-word code supplies the attaining lower bound.

## Verification
Run `python3 verify.py` from the directory containing `verify.py`, `census.tsv`, and `optima.tsv` (Python standard library only). The program regenerates all graphs without reading their adjacency matrices from a file. It verifies the entire initial capacity profile, enumerates all optimal codebooks, checks the supplied complete list by independent word-level deletion and overlap tests, compares the recorded clique census byte-for-byte, and verifies the three symmetry orbits. It prints `VERIFY_OK` on success.

The exact oriented clique sizes and counts are recorded in `census.tsv`; the entire list of twelve optimal length-ten codebooks is recorded in `optima.tsv`. An independent mixed-integer formulation using variables for eligible words and incompatibility-edge inequalities also returned the optimum of nine at length ten. The reproducible proof does not depend on that solver or on numerical tolerances.

## Relationship to prior work
The non-overlapping condition is the standard cross-bifix-free condition treated by Blackburn and by Chee, Kiah, Purkayastha and Wang. The latter report the unrestricted binary length-ten non-overlapping maximum \(24\), but impose no single-deletion-correction constraint. Sloane's survey of deletion codes, building on the Varshamov–Tenengolts/Levenshtein tradition, treats disjoint deletion descendants without the non-overlapping condition. A later exact-optimality account by No (2019) confirms the unrestricted length-ten deletion-code maximum \(94\). Neither one-constraint optimum determines the simultaneous optimum \(9\) or the twelve equality cases. Heymann, Ferreira and Swart considered combining synchronization and deletion correction for *permutation* codes over larger position-distinguishing alphabets; their construction does not imply an optimum for binary cross-bifix-free codes. No claim is made that the two word-level constraints, without a separate stream model, prove end-to-end continuous-stream recovery from deletions.

## Limitations
The exhaustive classification stops at length ten. It gives no formula or asymptotic capacity beyond that length, no bound on the delay to resynchronize after deletions in concatenated transmissions, and no channel-specific performance guarantee. Historical priority remains vulnerable to an unindexed earlier joint-code classification even though the cited primary results address different constraints or alphabets.
