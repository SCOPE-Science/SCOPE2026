# Location-dominating code reconfiguration on the dodecahedral graph: token jumps are already slides

## Finding
For the dodecahedral graph \(D\cong GP(10,2)\), the minimum size of a locating-dominating vertex set is \(7\), and exactly \(220\) vertex sets attain that minimum. Let \(R_J\) join two such minimum sets when one is obtained from the other by deleting one vertex and inserting one arbitrary previously unselected vertex (token jumping). Let \(R_S\) apply the additional requirement that the deleted and inserted vertices are adjacent in \(D\) (token sliding). Then **the two edge sets coincide exactly**, \(R_J=R_S\). This common graph has \(220\) vertices, \(570\) edges, and degree distribution \(120\) vertices of degree \(4\), \(40\) of degree \(6\), and \(60\) of degree \(7\). It is connected, with radius \(8\) and diameter \(9\).

## Assumptions and scope
The graph is labeled by \(u_i,v_i\) for \(i\in\mathbb Z/10\mathbb Z\), with exactly the edges \(u_iu_{i+1}\), \(u_iv_i\), and \(v_iv_{i+2}\) for each index \(i\) (undirected and without duplicate edges). A vertex set \(S\) is locating-dominating when for all distinct \(x,y\notin S\), the two sets \(N_D(x)\cap S\) and \(N_D(y)\cap S\) are nonempty and different. No restrictions are imposed on the neighborhood signatures of vertices inside \(S\). The finding concerns only minimum-cardinality locating-dominating sets in this one fixed graph. It does not claim that jumping and sliding are equivalent on other graphs, or on larger locating-dominating sets of this graph.

## Proof
This is a finite exhaustive theorem, established by complete enumeration with explicit terminating predicates rather than sampling. Index \(u_i\) by \(i\) and \(v_i\) by \(10+i\). Form the twenty closed-neighborhood bitmasks \(B_x=\{x\}\cup N_D(x)\), as specified in `checks/verify_ld_python.py` and independently constructed in `checks/verify_ld_cpp.cpp`. For an integer bitmask \(s\) encoding \(S\), test the exact predicate
\[
P(s)\iff \left(\forall x\notin S:\;s\mathbin{\&}B_x\ne0\right)\ \land\ \left|\{s\mathbin{\&}B_x:x\notin S\}\right|=20-|S|.
\]
Since \(x\notin S\), intersecting the closed neighborhood or open neighborhood with \(S\) gives the same set. Consequently, the predicate is necessary and sufficient for locating domination, with no heuristics.

The Python checker loops over every \(k\)-subset of the twenty vertices for each \(1\le k\le7\), testing this predicate; the C++ checker independently scans all twenty-bit masks and retains those with size at most seven. Both exhaustive methods establish that the counts are \(0\) for each \(1\le k\le6\) and exactly \(220\) for \(k=7\). No empty set is a locating-dominating set because it cannot dominate any vertex. Thus the minimum size is exactly seven and the list of minimum states is complete.

For each listed state \(s\), the programs examine **every** ordered pair \((a,b)\) with \(a\in S\) and \(b\notin S\). The replacement state is the bitwise exclusive-or \(t=s\mathbin{\hat{\ }}(1\ll a)\mathbin{\hat{\ }}(1\ll b)\). Membership of \(t\) in the complete state dictionary is necessary and sufficient for a legal token jump. Every such accepted replacement is checked to satisfy the actual graph-edge condition \(ab\in E(D)\); the Python implementation also constructs the restricted slide adjacency separately and directly compares the two adjacency collections. This proves \(R_J=R_S\), without assuming it from any general reachability theorem. Both implementations count \(1140\) directed incidences, hence \(570\) unordered edges, and reproduce the degree distribution.

Finally, breadth-first search from each of the \(220\) states on the complete adjacency graph computes exact finite shortest-path distances. All vertices are reached from every start; the smallest eccentricity is \(8\), and the largest is \(9\). Breadth-first search is exact for unweighted graphs, completing the radius, diameter, and connectivity assertions. All loops have explicit finite bounds and the two implementations use different enumeration orders and data structures.

## Verification
Run `python3 checks/verify_ld_python.py` under Python 3 (standard library only). Compile and execute `c++ -std=c++17 -O2 checks/verify_ld_cpp.cpp -o /tmp/verify_ld && /tmp/verify_ld` using a C++17 compiler. Each checks all lower cardinalities, all optimal states, every possible token replacement, the coincidence of jumping and sliding, the state degree distribution, connectivity, radius and diameter. The two programs report `PYTHON_LD_PASS` and `CPP_LD_PASS` respectively. The programs are full, standalone computational certificates of this finite claim; output strings alone would not suffice without evaluating the enumeration logic.

## Relationship to prior work
Balbuena, Foucaud and Hansberg (2014 preprint; published 2015) develop locating-dominating and identifying-code bounds on graphs of girth at least five, covering general cubic girth-five graphs as a class but not determining the minimum locating-dominating state-space geometry of \(GP(10,2)\). Hernando, Mora and Pelayo (2013) study global location-domination and distinguish locating-dominating sets by external-vertex neighborhood signatures. General reconfiguration literature distinguishes unrestricted token jumps from adjacency-restricted token slides. Those general definitions, bounds, and algorithms do not imply equality of the two entire edge sets for the minimum locating-dominating layer of the dodecahedral graph, nor the enumerated distance geometry. Similarity searches for this precise graph, invariant, and move model found no covering published statement, but absence from searched indexes cannot prove historical novelty.

## Limitations
The theorem is a fixed twenty-vertex exact classification, not an infinite-family assertion. Its proof is exhaustive and computational, using two auditable independent-source implementations rather than a short conceptual formula for the \(220\) sets. The literature search cannot exclude obscure, unpublished, or unindexed equivalent calculations; independent scholarly priority review has not occurred. Reproducing the result requires executing the included source code with its assertions enabled.
